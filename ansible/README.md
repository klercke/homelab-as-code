# Ansible

After OpenTofu builds hosts, Ansible configures them.
It reads the registry entries through `inventories/protonet/group_vars/all/hlac.json`, which is generated by `terraform/substrate`.
This keeps hosts, roles, addresses, and services in sync with the values OpenTofu uses.

Everything is run through the [Justfile in the repo root](../Justfile) (`just base`, `just role <name>`, etc.).
Each recipe runs `ansible-playbook` through `direnv` in this directory, which loads the necessary credentials from `.envrc`.

## Inventories

All three inventories live in `inventories/protonet/` and are logically combined into one "protonet" inventory.

| Inventory | Hosts | Source |
|---|---|---|
| `proxmox.yml` | Every Proxmox VE VM with the `hlac` tag, grouped by its tags (`tag_hlac`, `tag_role_<role>`, ...) | Proxmox API, at run time |
| `devices.yml` | Active physical devices with a management address, grouped as `device_role_<role>` | Generated by `terraform/substrate` |
| `cloud.yml` | Cloud hosts from `registries/cloud.yaml`, in the same `tag_` groups as VMs | Generated by `terraform/substrate` |

Because cloud hosts share the VM group names, a playbook that targets `tag_role_web` reaches a Linode exactly like it would reach a VM.

## Roles

| Role | What it does |
|---|---|
| `base` | Basic configuration for every Rocky host: users and SSH, DNS resolvers, IPv6, updates, bootloader, node_exporter. |
| `proxmox` | Shared by every Proxmox product host (PVE, PBS): IPMI tool, a static IPv6 address, email notification configuration, and skipping the subscription dialog. |
| `hypervisor` | Proxmox VE nodes: cluster membership and QDevice, bridges, zram swap, VFIO passthrough, the VM pool, and PBS storage shared across the cluster. |
| `pbs` | Proxmox Backup Server: repositories, the datastore pool, prune/GC/verify schedules, and API tokens for the PVE hosts. |
| `postgres` | The shared PostgreSQL server, with a metrics exporter and backups. |
| `valkey` | The shared Valkey server, for cache and queues. |
| `netbox` | NetBox, using the shared Postgres and Valkey. |
| `powerdns` | PowerDNS Authoritative. Only hosts with the `recursor` role can reach it. |
| `recursor` | PowerDNS Recursor, the resolver every client uses. Forwards internal zones to the `powerdns` hosts. |
| `kea` | ISC Kea DHCP. Subnets and reservations are written by `terraform/platform`, not by this role. |
| `monitoring` | Prometheus and Grafana, scraping every host and service in the registries, with provisioned dashboards. |
| `llm` | The LLM gateway: LiteLLM and an embedding server as Podman quadlets, with routes generated from `registries/models.yaml`. |
| `immich` | Immich and its add-ons as Podman quadlets, with its own Postgres, Valkey from valkey01, and the media library mounted from the NAS. |
| `caddy` | Caddy with the Cloudflare DNS module, in one of three modes. `internal`: a wildcard certificate for `*.int.ptxe.dev`, sites from `public_services`. `edge`: public ingress, a certificate per exposed hostname. `site`: static sites (used by `web`). |
| `netbird` | NetBird routing peers. They only forward: no resolver changes, no routes from other peers. |
| `wings` | Pelican Wings game server nodes, each with its own SFTP port forwarded from the WAN. |
| `web` | Static sites and the `webssh` server: deploy roots, an rrsync-restricted deploy key per site, and the webssh service. |

## Tags

Every role task carries tags, so a role can be rerun in part.
Untagged runs (`just base`, `just role kea`) still run everything.
Playbook `pre_tasks` that load secrets or build variables are tagged `always`, so they run on tagged runs too.

| Tag | Covers |
|---|---|
| `install` | Vendor repos, packages, downloads, users, schema setup. This is the slowest part of most roles. |
| `config` | Templates, config files, and their validation. |
| `firewall` | firewalld rules. |
| `service` | Enabling and starting units. |
| `dns`, `ipv6`, `ssh`, `users`, `updates`, `bootloader`, `node_exporter` | Areas of the base role. |
| `cluster` | Cluster membership and QDevice in the hypervisor role. |
| `prometheus`, `grafana`, `dashboards` | Areas of the monitoring role. |
| `exporter`, `backups` | Areas of the postgres role. |
| `keys` | LiteLLM key registration in the llm role. |
| `deploy`, `webssh`, `logging` | Deploy roots and keys, the webssh service, and journal retention in the web role. |

Examples:

```sh
just base --limit pdns01 --tags dns
just base --skip-tags install
just role kea --limit kea01 --tags config
just role monitoring --tags dashboards
just role web --tags deploy
```

A tagged run can skip a step that an untagged first run would do, so build new hosts with an untagged run.

## Secrets

Playbooks load their secrets from the SOPS-encrypted files in `secrets/` in `pre_tasks`.
See [`SOPS.md`](../SOPS.md) for how they are encrypted, edited, and read.
